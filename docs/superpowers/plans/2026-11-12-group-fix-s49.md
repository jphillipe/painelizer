# S49 — Conserto em grupo (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um botão na linha da causa aplica a mesma edição a todas as aberturas dela, num passo só de desfazer: "Set header" (todas ou por tipo) e, para a altura de porta × header, duas opções que dizem se mudam o framing.

**Architecture:** O editor ganha uma ação genérica `applyEdits` (lista de edições → um commit, um Ctrl+Z), que a sugestão por IA (S51) também vai usar. `lib/editor/group-fixes.ts` decide que conserto cada causa oferece (`groupFixFor`) e monta as edições (`setHeaderEdits`, `doorHeightEdits`). A lista de issues mostra o formulário/botões e devolve as edições; o workspace despacha. Só `packages/web`.

**Tech Stack:** TypeScript 7, React 19 / Next.js 16, vitest (+ jsdom), pnpm.

**Spec:** `docs/superpowers/specs/2026-11-12-issues-by-cause-design.md` — §3 "Conserto em grupo".

## Global Constraints

- Nada é aplicado sem um clique do humano; o que muda o framing diz isso no botão.
- O header vai **direto em cada abertura** (`header`), nunca pelo header schedule (a entrada exigiria kings, que passariam por cima da tabela de vento).
- Só as aberturas **listadas na linha** são editadas.
- Um passo só de desfazer por conserto.
- `packages/core` e `packages/cli` não mudam. Textos da tela em inglês. Um commit no fim; `pnpm check` e `pnpm --filter web build` antes.

## Review Focus

1. Tipo de porta usado também por aberturas que NÃO estão na linha: "usar a altura do header como RO" não pode mexer no tipo (mudaria portas fora da causa) — edita as aberturas. → teste na Task 2.
2. Abertura da linha que já tem `headerMark`: "Set header" troca por `header` direto e tira a marca (senão as duas brigam). → teste na Task 2.
3. Seção de header inválida no formulário ("2x13", vazio) ou plies < 1: o botão Apply não aplica e o campo mostra o erro. → teste na Task 3.
4. Abertura apagada entre a checagem e o clique: a edição dela é ignorada; se nenhuma sobra, nada muda e não entra passo de desfazer. → teste na Task 1.
5. Desfazer: um Ctrl+Z desfaz o conserto inteiro (13 aberturas), não uma por vez. → testes nas Tasks 1 e 3.

### Task 2: O que cada causa oferece e as edições

**Files:** Create `packages/web/src/lib/editor/group-fixes.ts`; Test `group-fixes.test.ts`, `issue-causes.test.ts` (pela checagem real)

**Interfaces (Produces):**
```ts
export interface OpeningRef { wallId: string; openingId: string }
export interface HeaderScope { key: string; label: string; openings: OpeningRef[] } // 'all' | 'tag:<T>'
export type GroupFix = { kind: 'setHeader'; scopes: HeaderScope[] } | { kind: 'doorHeight'; roughHeight: number; headerBase: number; openings: OpeningRef[] };
export function groupFixFor(group: IssueGroup, openings?: ReadonlyMap<string, OpeningInfo>): GroupFix | undefined;
export interface HeaderInput { section: string; plies: number; jackStuds?: number }
export function setHeaderEdits(scope: HeaderScope, header: HeaderInput): DraftEdit[];
export function doorHeightEdits(fix: Extract<GroupFix, { kind: 'doorHeight' }>, choice: 'roFromHeader' | 'headerFromRo', draft: ProjectDraft): DraftEdit[];
```
- `setHeader`: famílias `HEADER_OUT_OF_TABLE`, `FLAT_HEADER_CRIPPLES`, `FLAT_HEADER_SPAN`; escopos = `all` ("All 13 openings" / "This opening") e, havendo 2+ tipos, um por tag em ordem alfabética ("Type E2 (3)"; sem tag: "No type (2)"). Edição: `{ header: { section, plies, jackStuds? }, headerMark: undefined }`.
- `doorHeight`: família `DOOR_RO_HEIGHT_MISMATCH` com `roughHeight` e `headerBase` iguais em todas as ocorrências; senão, sem conserto. `roFromHeader`: por tipo quando TODAS as aberturas desse tipo no draft (sem `roughHeight` próprio) estão na linha → `openingType.roughHeight = headerBase`; senão `opening.roughHeight = headerBase`. `headerFromRo`: `opening.headerHeight = roughHeight`.
- [ ] Testes que falham (inclui Review Focus 1 e 2) e, no projeto inventado das quatro causas: "Set header" 2x12 × 3 em todas → a checagem não traz mais `HEADER_OUT_OF_TABLE`; `headerFromRo` → somem `DOOR_RO_HEIGHT_MISMATCH` **e** `FLAT_HEADER_CRIPPLES`; `roFromHeader` → some só `DOOR_RO_HEIGHT_MISMATCH`. Ver falhar, implementar, ver passar.
